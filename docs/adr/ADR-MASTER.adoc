== Introduction

The k8s-1m project is a research effort to scale Kubernetes to 1 million nodes.
This requires making several non-standard architectural decisions around networking, state management, and scheduling.

Each ADR follows this format:
- *Status*: Proposal/Accepted/Deprecated/Superseded
- *Context*: The problem or motivation
- *Decision*: The chosen solution
- *Consequences*: Trade-offs (positive, negative, neutral)
- *Related Decisions*: Links to other ADRs
- *References*: Links to code, documentation, external resources

== Summary

These ADRs document the critical architectural decisions that enable scaling Kubernetes to 1 million nodes:

| ADR | Title | Status | Key Trade-off |
|-----|-------|--------|---------------|
| 0001 | Use IPv6 Exclusively | Accepted | Vast address space vs. IPv4 compatibility |
| 0002 | Use mem_etcd | Accepted | 20x write throughput vs. no durability |
| 0003 | Distributed Scheduler | Accepted | Near-linear scaling vs. increased complexity |
